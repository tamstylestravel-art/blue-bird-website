# Rule: CSS Layout Best Practices
เวลาทำการปรับแก้ CSS, Tailwind Classes หรือการจัด Layout (การจัดวางโครงสร้างหน้าเว็บ) ให้ปฏิบัติตามกฎดังนี้:

**สิ่งที่ห้ามทำ:**
- ห้ามใช้ `!important` (หรือใน Tailwind คือการใส่ `!` นำหน้า class) โดยเด็ดขาด 
- ห้ามใช้ `position: absolute` (หรือคลาส `absolute`) ในการจัดวาง Layout ปกติ

**ข้อยกเว้น:**
- อนุญาตให้ใช้ `position: absolute` (หรือ `fixed`) ได้ **เฉพาะกรณีที่จำเป็นจริงๆ เท่านั้น** เช่น การทำ Modal, Tooltip, Dropdown Menu, หรือ Overlay

**สิ่งที่ควรทำแทน:**
- ให้ใช้ Flexbox (`flex`) หรือ Grid (`grid`) ในการจัดโครงสร้าง Layout เสมอ เพื่อให้การตอบสนอง (Responsive) ทำงานได้อย่างสมบูรณ์และดูแลรักษาโค้ดได้ง่าย
- คำนึงถึงการออกแบบที่รองรับทุกขนาดหน้าจอ (Responsive Design) เสมอ
- สำหรับขนาด (Width/Height) หรือระยะห่าง (Margin/Padding) ห้ามกำหนดเป็นหน่วย Pixel (`px`) ตายตัว ให้ใช้หน่วยสัมพัทธ์เช่น `%`, `vw`/`vh`, หรือ `rem`/`em` เสมอ เพื่อให้การแสดงผลยืดหยุ่นตามหน้าจอ
- เวลาแก้ไข CSS หรือตั้งชื่อคลาส ให้พยายามใช้คลาสที่มีความเฉพาะเจาะจงผูกติดกับ Component นั้นๆ เสมอ (Component-scoped) หรือใช้ **CSS Modules (เช่น `.module.css`)** เป็นหลัก
- **การตั้งชื่อคลาส (Naming Convention):** ให้ใช้รูปแบบ **BEM (Block__Element--Modifier)** หรือต้องตั้งชื่อโดยมี "ชื่อ Component" นำหน้าเสมอ (เช่น `.navbar__button`) เพื่อให้สามารถระบุได้ทันทีว่าคลาสนี้เป็นของส่วนไหนของโปรแกรม
- **ห้ามเขียน Selector ซ้อนกันลึกเกิน 3 ชั้นเด็ดขาด** (เช่น ` .card .body div span`) เพื่อป้องกันปัญหาเรื่องความเฉพาะเจาะจง (Specificity Wars) และทำให้โค้ดดูแลรักษาง่ายในอนาคต
- **ห้ามเขียนสไตล์ใหม่ลงในไฟล์ Global CSS ส่วนกลางเด็ดขาด** (ยกเว้นผู้ใช้จะสั่งโดยตรง) เพื่อป้องกันไม่ให้สไตล์ไปกระทบหรือทำให้หน้าเว็บส่วนอื่นพัง

# Rule: Warn on Destructive Actions
หากคำสั่งหรือความต้องการของผู้ใช้มีความเสี่ยงสูงที่จะทำให้ระบบพัง โค้ดเสียหาย หรือเป็นการลบไฟล์/ข้อมูลที่สำคัญ ให้หยุดชะงักและทำการทักท้วงผู้ใช้ก่อนเสมอ

**แนวทางปฏิบัติที่ต้องทำ:**
- ประเมินผลกระทบของคำสั่งก่อนลงมือทำจริงเสมอ
- หากพบความเสี่ยง ให้พิมพ์ข้อความเตือนผู้ใช้อย่างชัดเจน (อาจใช้ Alert หรือข้อความที่เห็นได้ชัด)
- อธิบายสั้นๆ ว่าคำสั่งนั้นอาจส่งผลเสียอย่างไร
- เสนอทางเลือกอื่นที่ปลอดภัยกว่า (ถ้ามี) หรือรอให้ผู้ใช้ยืนยันกลับมาอย่างชัดเจนอีกครั้งก่อนจึงจะดำเนินการ
